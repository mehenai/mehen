Use credentials without reading them.

Access for agents. An agent uses your API keys without ever receiving them.

The agent asks Mehen to make the call. Mehen adds the key on the way out, only to the hosts the key is bound to, and scrubs supported echoes of it from the response, so the agent sees the result and never the key. The upstream service that receives the key, and whoever runs the vault, remain trusted.

Get started

One command on your own machine.

Run curl -fsSL https://mehen.dev/install | sh && mehen up on macOS, or Linux with glibc (WSL included). Windows is not supported yet. With Node.js, npx @mehenai/cli up does the same. Or paste the prompt above into your agent, and it runs the same steps and hands you each link. Run mehen up again at any time: it picks up where it stopped.

  1. 01

    The vault

    Starts on this machine at http://localhost:7787, on the loopback address only, as a service that starts again when you log in.

  2. 02

    Your passkey

    A page opens: make a passkey with Touch ID, your phone or a security key, save the recovery codes and create your workspace. No password.

  3. 03

    This machine

    Enrolled with its own key. Check the fingerprint the terminal shows, type the group the page hides, and accept with your passkey.

  4. 04

    Your agents

    The MCP server and skill go into Claude Code, Codex, Cursor, pi, Gemini CLI, OpenCode, VS Code and Claude Desktop, and the guard hooks into Claude Code, pi, Cursor and Codex.

Then mehen adopt scan finds the keys already in your .env files and CLI logins, and brings them in with one passkey. Run Mehen on your machine.

Test it yourself

Ask your agent for the key. It does not have it.

The claim is one you can check on your own machine in a few minutes.

  1. Run mehen up, then ask your agent to call an API you have a key for. It gives you a link; you type the key into the vault's page, not the chat.
  2. The agent makes the call through Mehen and gets the result.
  3. Now ask it to print the key, read your .env, or send the key to another host. It has a name, not a value; the guard stops the read, and the vault refuses any host outside the key's binding.

How it works

The agent asks. Mehen makes the call.

The key crosses from you to the vault once. After that, in relay and placeholder modes, the agent handles only a placeholder or the response after the vault has scrubbed supported echoes of the key. The vault scrubs credential echoes in raw, URL-encoded, JSON-escaped and supported base64 forms. It cannot catch arbitrary transformations, and values shorter than six characters are not redacted.

The guard hooks

Agents read files. The guard checks first.

mehen up installs guard hooks in Claude Code, pi, Cursor and Codex that stop an agent reading .env files, key files and CLI logins, or pasting a key into a command or a file, and tell it what to use instead. They answer on the machine in milliseconds, with no network. mehen guard warn only warns; mehen guard off turns them off.

The hooks are not the security boundary; the vault's bindings are. They keep an agent from handling a key by accident or because a page told it to. The guard hooks.

Where it runs

Your machine, a machine you own, or a team's.

The same vault in each place: the same bindings, approvals, audit chain, command and MCP tools. One machine can be enrolled in a local vault and a Cloud workspace at once.

  1. This machine

    mehen up

    The vault on localhost, beside your agents. It keeps keys out of the model's context, transcripts, logs, shell history and .env files. A program running as you can still read the vault's own files; the threat model says how to close that.

  2. Another machine you own

    mehen serve

    A box at home or on your tailnet, behind TLS from Tailscale serve or Caddy. Your laptops enrol with MEHEN_VAULT_URL, and the vault's files stay off the machines your agents run on. Run it on another machine.

  3. Mehen Cloud, for teams

    Invite only for now

    Shared workspaces, members and roles, teams and approvals from your phone, at app.mehen.dev. Ask for an invitation.

Invited to a Cloud workspace?

A member's invitation is for one email address: its link asks you to verify that address with Google or a code Mehen emails, then to create a passkey and save recovery codes. Then give your agent this prompt; it installs Mehen and requests enrolment. You accept your own machine with your passkey. A guest's machine also needs admission; a team's machine is admitted by a workspace owner or admin.

Follow https://docs.mehen.dev/setup.md to connect this machine to Mehen workspace <your-slug> at https://app.mehen.dev. I will approve it in my browser; never ask me for a key, password or secret.

The Connect an agent page fills in the slug and, when available, a connect code. Without a code, your agent gives you the exact enrolment link. Use it with a team.

Where keys leak today

A key the agent can read is a key that leaks.

Secrets in files, transcripts, logs and shell history can be exposed to tools and people with access to them. Once a model has read a secret, output masking cannot remove it from that context.

  • .envReadable by the tools and people with access to the file.
  • the transcriptKept as long as the provider and your settings keep it.
  • the logsRequest bodies, tool results, stack traces.
  • shell historyOne export, written to a file.
  • prompt injectionCan misuse whatever the agent can access.

Approvals

Humans approve what they see.

The request the approval is bound to, the binding it runs under, and why it waited. One passkey, and the agent carries on. A held request is not sent until then.

  • Rules decide what waits: writes, sends, production. A host outside the binding is refused outright.
  • Approve from the vault's page, phone or laptop.
  • Every decision lands in the audit chain.

The vault

Every secret has a destination.

Each credential is bound to hosts, paths and methods. Sent anywhere else, it is refused, with a reason and, where Mehen can, the next step.

The CLI and MCP

Placeholders in, answers out.

Use mehen run with HTTP clients that honour its proxy and CA settings: they receive placeholders without changing application code. Over MCP, the agent names the capability, never the value. Refusals include a reason and, where Mehen can, the next step.
